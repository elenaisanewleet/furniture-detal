---

## Назначение документа

Этот документ — точка входа для любой новой сессии работы над интернет-магазином
Semers, в первую очередь локальной сессии на компьютере владельца. Он отвечает на
четыре вопроса: что уже сделано, что сломано, что решает владелец, и что делать
следующим шагом.

Документ лежит в репозитории и меняется вместе с кодом. Если решение принято, но
не записано сюда — для проекта его не существует.

## Ключевой принцип

**Сайт считается готовым не тогда, когда он красивый, а тогда, когда через него
прошёл первый настоящий заказ с деньгами.**

Всё остальное — вёрстка, тексты, анимации, переводы — подчинено этому.

## 2. Что уже сделано

### 2.1. Сайт стал лёгким (21.09.2026, закоммичено и запушено)

Владелец сказал: «сайт слишком грузный, прокруты лагают». Это было измерено, а не
на глаз. Замеры на одной и той же странице, 1440×900:

| | было | стало |
| --- | --- | --- |
| потерянных кадров при скролле | 45 % | **1 %** |
| то же при замедлении процессора в 4 раза | 48 % | **4 %** |
| заблокированный главный поток | 1259 мс | **0 мс** |
| трафик главной страницы | 1174 КБ | **325 КБ** |
| JavaScript | 673 КБ | **39 КБ** |
| загрузка | 901 мс | 272 мс |

Что для этого убрано, в порядке вклада:

1. **Зерновой оверлей** — слой в четыре экрана размером, с режимом наложения,
   перерисовывался десять раз в секунду на каждой странице ради текстуры в 7 %
   прозрачности. Один он давал 24 пункта из 45.
2. **WebGL-герой** — 26 000 частиц на three.js, превращавших яблоко в батончик на
   протяжении двух экранов прокрутки. 12 пунктов и около 550 КБ кода. Отдельно
   важно: его запасной вариант был сломан — без поддержки WebGL секция всё равно
   занимала два экрана, холст был невидим, а фотография под ним показывалась на
   22 % прозрачности. То есть часть посетителей видела два экрана пустоты.
   Сейчас герой — обычная фотография рядом с заголовком, одинаковая для всех.
3. **Lenis** — «плавная прокрутка», которая забирала скролл у браузера и отдавала
   его на кадр-два позже. Именно это и ощущается как лаг.
4. **GSAP со ScrollTrigger** — 49 КБ ради трёх вещей, которые браузер делает сам:
   горизонтальная лента теперь на CSS scroll-snap, подсветка блоков — на одном
   IntersectionObserver.
5. **Общий файл стилей** — каждая страница скачивала 280 КБ, чтобы использовать
   20–40 КБ. Теперь у каждой страницы свой файл.

Зависимости `three`, `gsap`, `lenis` удалены из проекта полностью. Синхронизация
на Higgsfield больше не требует ручного `bun add`.

Проверка пройдена целиком: 141 тест, 0 ошибок типов, 121 страница, SEO, микроразметка,
безопасность и переводы — чисто, включая перевод трёх новых предложений на русский
и латышский.

## 3. Главная проблема: магазин не принимает деньги

Это не недоделка, а разрыв между тем, что есть, и тем, что владелец называет
«запуском интернет-магазина».

Как работает оформление заказа сейчас (`api/order.js`, `src/pages/[...locale]/checkout.astro`):

```
покупатель нажал «оформить»
  → заявка уходит в Telegram и на почту
  → на экране: «мы подтвердим письмом и пришлём ссылку на оплату
                в течение одного рабочего дня»
  → дальше человек выставляет счёт руками
```

В коде это записано честно: «Payment is intentionally not here yet».

Следствия:
- покупатель не может купить в момент, когда захотел;
- каждый заказ требует ручной работы;
- остатки не резервируются, два человека могут купить последнюю коробку;
- конверсия теряется на разрыве между «хочу» и «оплатил».

**Это задача номер один.** Пока её нет — всё остальное косметика.

## 4. Что решает владелец

Эти вопросы нельзя решить из кода. До ответа работа по ним стоит.

1. **Приём оплаты.** Какой способ подключаем первым — Stripe, банковский
   эквайринг, Paysera / Klix / Montonio, или на первом этапе честно живём на
   «заявка + счёт вручную». Нужен ответ и доступ к аккаунту.
2. **Белёвская пастила в позиционировании.** Владелец сказал: «БЕЛЕВ ПАСТИЛА
   здесь не причем». В исходниках 90 упоминаний, на главной было 19. Часть
   убрана. Но два товара называются «Belyov Apple Pastila» и имеют штрихкоды —
   это упаковка, её переименование стоит денег. Решение за владельцем:
   переименовать товары или оставить название товара, убрав Белёв из истории бренда.
3. **Сколько языков при запуске.** Сейчас три. Для Риги нужны латышский и русский,
   английский — на экспорт. Три языка втрое увеличивают работу над каждым текстом.
4. **Что режем.** Постраничное решение — см. раздел 6.
5. **Регистрационный номер и номер НДС.** Не публикуются, пока владелец их не
   подтвердит. По закону ЕС реквизиты продавца на сайте обязательны, поэтому
   запуск без них невозможен.
6. **Доставка.** С кем договор — Omniva, DPD, Venipak, Latvijas Pasts, курьер,
   самовывоз. Сроки и цены на сайте должны совпадать с реальностью.

## 5. Как поднять проект на своём компьютере

Нужны: Node.js 20 или новее и Git.

```
git clone https://github.com/elenaisanewleet/furniture-detal.git
cd furniture-detal/semers
git checkout claude/semers-ecommerce-site-re12yb
npm install
npm run dev          # сайт на http://localhost:4321
```

Проверить, что ничего не сломано:

```
npm run verify       # тесты, сборка, HTML, SEO, микроразметка, безопасность, переводы
```

Проверки в настоящем браузере (доступность, путь покупки, админка, анимация)
запускаются отдельно — как именно, написано в `DEPLOY.md`.

Переменные окружения для приёма заявок (без них форма подставляет письмо в почтовый
клиент, ничего не теряется): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
`RESEND_API_KEY`, `ORDER_TO_EMAIL`. Значения — у владельца, в репозиторий не кладутся.

## 6. Что оставляем, что режем

Решение по каждой странице принимается по одному критерию: **помогает ли эта
страница продать коробку пастилы завтра.**

Обязательно остаётся:
- главная, каталог, карточки товаров, корзина, оформление, страница «спасибо»;
- контакты;
- три юридические страницы — без них магазин в ЕС не запускают.

Под вопросом (решение владельца, см. раздел 4):
- отдельные страницы истории бренда, производства и «почему пастила» — три больших
  текста, 1786 строк; кандидаты на объединение в одну страницу «О нас»;
- оптовый раздел — это другой бизнес, ему хватит формы;
- журнал из трёх статей — задел под поиск, не под запуск;
- страница «где купить» — нужна, только если есть точки продаж;
- 8 страниц коллекций при 10 товарах — вероятно, хватит одного каталога;
- конструктор коробки — усложняет корзину.

Контентная обвязка — 3358 строк, это 40 % всего кода страниц. Ни одну из этих
страниц никто не просил.

**Тяжёлая версия сохранена** на ветке `backup/site-heavy`. Резать можно смело:
вернуть всегда получится.

## 7. Порядок работы

Принят по образцу SEMERS OS v1.0.

1. Один шаг — одна задача. Задача либо доведена до конца, либо явно названа
   незаконченной. «Почти готово» не бывает.
2. Любое утверждение о качестве подтверждается замером или ссылкой на файл.
   «Стало быстрее» без цифры — не результат.
3. Каждое изменение проходит `npm run verify` до коммита. Красная проверка не
   коммитится.
4. Работа ведётся только на ветке `claude/semers-ecommerce-site-re12yb`.
5. Решения владельца записываются в раздел 4 этого документа. Устное решение,
   не попавшее сюда, будет забыто.
6. Сделанное записывается в журнал работ ниже — коротко, с датой и результатом.

## 8. Красные флаги

Останавливаемся и спрашиваем владельца, если:

- обещание на сайте расходится с реальностью (срок доставки, наличие, цена);
- на сайт просится внутренняя цифра бизнеса или имя клиента — они на сайт не идут;
- требуется опубликовать регистрационный номер или НДС до подтверждения владельцем;
- изменение затрагивает название товара, у которого есть штрихкод;
- проверка не проходит, а изменение всё равно хочется выложить.
