# Промт для Claude Code

Скопируйте всё, что ниже разделителя, в чат с Claude Code — в папке, куда распакован этот пакет.

---

Задача: довести до продакшена многостраничный сайт мебельной мастерской (село Архангельское,
Ульяновская область). Цель сайта одна — принимать заявки на работу. Вторая цель — местная
поисковая выдача: сайт должен выигрывать у конкурентов по региональным запросам.

## Что уже есть

В папке `design/` — 17 файлов: готовый прототип сайта на чистом HTML/CSS/JS. Это **дизайн-референс**,
а не продакшен-код: он показывает структуру страниц, копирайт, разметку и поведение форм.
Копировать его построчно не нужно — нужно перенести те же экраны в нормальную сборку.

`SPEC.md` — полное описание страниц, компонентов, токенов и поведения. Читайте его первым.

Два источника, которые надо прочитать в GitHub перед началом:

1. **`elenaisanewleet/furniture-site`** (Astro, ветка HEAD) — это задеплоено на
   detal-beta.vercel.app. Оттуда берём **визуальный язык и качество проработки**:
   `src/styles/tokens.css`, `src/styles/base.css`, `src/styles/fonts.css`, `src/lib/drawings.ts`,
   `src/scripts/task-form.ts`, `src/scripts/part-finder.ts`. Палитра, шрифты (Golos Text +
   JetBrains Mono, локально), угловые метки вместо рамок, чертежи вместо фотографий, механическое
   движение — всё это переносим целиком.
2. **`elenaisanewleet/furniture-detal`** (ветка main, папка `ui_kits/master-site`) — текущий сайт
   мастерской. Оттуда берём **содержание**: услуги, станки, определитель детали, форму заявки.

Важно: контент `furniture-site` описывает другую мастерскую и другой набор работ. Берём оттуда
оформление, а не тексты и не список услуг.

## Стек

Astro + чистый CSS с кастомными свойствами, как в `furniture-site`. Никакого UI-фреймворка,
никакого CSS-фреймворка. Статическая сборка, деплой на Vercel. Если считаете, что для этой задачи
лучше другой стек — скажите почему до того, как начнёте.

## Что сделать

1. Перенести 13 страниц из `design/` в Astro: главная, шесть услуг, определитель детали, станки,
   заявка, контакты, 3D-модель, каталог объектов. Разметка страниц и внутренние ссылки — по `SPEC.md`.
2. Палитра и типографика «Деталь 73» в прототипе уже применены (`design/site.css`,
   `tokens-detal73.css`). В продакшене: положить шрифты локально (`furniture-site/public/fonts/`),
   добавить тёмную тему и слой чертежей `--draw-*` из полного `tokens.css`.
3. Форма заявки: номер вида `73-4821`, четыре канала (WhatsApp, Telegram, звонок, почта), запись
   голосового. Сейчас номер живёт в `sessionStorage` и никуда не уходит. Нужен минимальный бэкенд
   (serverless-функция на Vercel), который принимает заявку, пишет её в хранилище и отправляет в
   Telegram-бота `@detal_zakaz_bot`. Голосовое — загрузка файла на тот же эндпоинт.
4. SEO: см. раздел «SEO» в `SPEC.md`. Проверить, что каждая страница имеет свой `title`,
   `description`, `canonical`, Open Graph, Schema.org (`LocalBusiness` / `Service` / `FAQPage` /
   `BreadcrumbList`), и что `sitemap.xml` генерируется сборкой, а не лежит руками.
5. Заменить домен `furniture-detal.vercel.app` на реальный, когда он будет — вынести его в одну
   переменную окружения, а не в 13 файлов.

## Чего не делать

- Не придумывать факты: стажа, цен, сроков, гарантий и отзывов у мастера нет — на сайте их быть
  не должно. Наличие на складе формулируется как «уточните перед поездкой».
- Не ставить фотостоки. Фотографий мастерской в публикацию нет; вместо них чертежи и 3D-рендеры.
- Не добавлять иконочный шрифт и не менять шрифты.

Начните с чтения `SPEC.md` и обоих репозиториев, потом предложите план по файлам — и дождитесь
подтверждения, прежде чем писать код.
