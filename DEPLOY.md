# Выкладка и настройка

## Первый раз

1. vercel.com → **Add New → Project** → **Import Git Repository** → выбрать
   этот репозиторий.
2. Framework Preset: **Astro**. Build Command, Output Directory и остальное
   Vercel возьмёт из `vercel.json` — менять ничего не нужно.
3. **Deploy**. Через минуту появится адрес вида `что-то.vercel.app`.

Каждый следующий коммит в ветку обновляет сайт сам.

## Переменные окружения

Vercel → проект → **Settings → Environment Variables**. Ни одна не
обязательна: без них сайт работает, но заявка уходит только в мессенджер, а
номер выдаёт браузер.

### Домен

| Переменная | Что делает |
|---|---|
| `SITE_URL` | Боевой адрес сайта, например `https://мастерская.рф` |

Пока переменной нет, адрес берётся из системной
`VERCEL_PROJECT_PRODUCTION_URL` — то есть из `*.vercel.app`. Отсюда его
читают canonical, Open Graph, `sitemap.xml`, `robots.txt` и schema.org: в
самих страницах домена нет ни разу.

### Заявки

| Переменная | Что делает |
|---|---|
| `PUBLIC_LEAD_ENDPOINT` | Куда форма отправляет заявку. Поставьте `/api/zayavka` |
| `PUBLIC_MAIL` | Адрес почты. Задан — появляется кнопка «Отправить на почту» |
| `PUBLIC_TG_BOT` | Имя бота без `@`. Задано — заявки идут в бота, а не в личный Telegram |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather |
| `TELEGRAM_CHAT_ID` | Куда бот присылает заявки |

**Важно:** `PUBLIC_LEAD_ENDPOINT` не задан — форма работает по-старому:
номер выдаёт браузер, заявка уходит только в мессенджер, и в подтверждении
об этом сказано прямо. Обещать доставку, которой не было, сайт не станет.

### Поиск

| Переменная | Что делает |
|---|---|
| `PUBLIC_YANDEX_VERIFICATION` | Код из Яндекс.Вебмастера |
| `PUBLIC_GOOGLE_VERIFICATION` | Код из Google Search Console |
| `PUBLIC_METRIKA_ID` | Номер счётчика Яндекс.Метрики |

Пока коды не заданы, метатеги не выводятся вовсе.

**Что сделать сразу после появления домена — по порядку:**

1. **Яндекс.Вебмастер** → добавить сайт → способ «Метатег» → положить код
   в `PUBLIC_YANDEX_VERIFICATION` → передеплоить → подтвердить.
   Там же: «Индексирование → Файлы Sitemap» → добавить
   `https://ваш-домен/sitemap-index.xml`.
2. **Google Search Console** — то же самое, код в
   `PUBLIC_GOOGLE_VERIFICATION`.
3. **Яндекс.Бизнес** — карточка организации. Для мастерской в селе это
   даёт больше, чем весь остальной SEO вместе взятый: карточка попадает
   в Карты и в выдачу с телефоном и кнопкой «позвонить». Адрес, часы
   работы и фотографии заполняет мастер — я их не выдумываю.
4. **Метрика** — без счётчика не видно, по каким запросам приходят
   и с каких страниц уходят, то есть SEO дальше делать вслепую.

### Хранилище заявок

Драйвер выбирается сам по тому, что задано.

| Задано | Что происходит |
|---|---|
| `KV_REST_API_URL` + `KV_REST_API_TOKEN` | Upstash Redis: сквозная нумерация `73-1001`, `73-1002`… и карточка заявки |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob: карточка заявки и файлы (снимки, голосовое) |
| ничего | Заявка уходит в Telegram и хранится там; номер выдаётся по времени |

Сквозную нумерацию даёт только Upstash: `INCR` атомарен, поэтому два
одновременных обращения не получат один номер. Без него номер собирается из
времени суток, и в карточке рядом всегда лежит полный `id`, который не
повторяется никогда.

Подключается в один клик: Vercel → **Storage** → **Upstash Redis** или
**Blob** → **Connect**. Переменные Vercel подставит сам.

## Как завести бота заявок

Бот `@detal_zakaz_bot` в задании упомянут, но не создан. Порядок такой:

1. В Telegram написать **@BotFather** → `/newbot` → имя и адрес бота.
   BotFather ответит токеном вида `1234567890:AA...`.
2. Написать своему боту любое сообщение — иначе он не сможет ответить.
3. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять оттуда
   `chat.id`.
4. Положить токен в `TELEGRAM_BOT_TOKEN`, id — в `TELEGRAM_CHAT_ID`,
   а имя бота без `@` — в `PUBLIC_TG_BOT`.
5. Передеплоить.

После этого заявки приходят в бота текстом, снимки — отдельными файлами
(документом, а не фотографией: Telegram сжимает фото, а по сжатой резьбе
деталь не опознать), голосовое — голосовым сообщением.

## Переезд на свой домен

1. Vercel → проект → **Settings → Domains** → добавить домен и прописать у
   регистратора записи, которые покажет Vercel.
2. Задать `SITE_URL` — весь сайт переедет сам: canonical, sitemap, robots,
   schema.org, Open Graph.
3. **Сделать новый домен основным**, чтобы старый `*.vercel.app` отдавал
   301, а не вторую копию сайта.

Третий шаг обязателен. Без него в выдаче останутся два одинаковых сайта,
которые растащат друг у друга позиции — а позиции и есть половина задачи.

## Старые адреса

Прототип жил на адресах вида `/stanki.html`. В `vercel.json` для всех
тринадцати страниц стоит 301 на новые адреса без расширения, так что
ссылки, которые успели куда-то попасть, не потеряются.
